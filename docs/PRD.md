# Guess Pokémon PRD

- 작성일: 2026-07-24
- 서비스명: Guess Pokémon
- 프로젝트 slug: `guess-pokemon`
- 상태: 공식 서비스 기준선

## 1. 서비스 개요

Guess Pokémon은 두 명이 방 코드를 공유해 실시간 포켓몬 스무고개를 진행하는 비상업 팬 웹 서비스다. 첫 경기에서 방장이 포켓몬을 고르고 상대방이 질문한다. 이후 재대결마다 역할을 바꾼다.

## 2. 해결하려는 문제

- 떨어져 있는 두 사용자가 별도 음성·채팅 도구 없이 같은 게임 상태를 보며 포켓몬 스무고개를 진행하고 싶다.
- 질문·답변·추측 횟수를 사람이 직접 세지 않고 시스템이 공정하게 관리해야 한다.
- 브라우저 새로고침이나 일시적인 네트워크 단절이 즉시 패배로 이어지지 않아야 한다.
- 로그인한 사용자가 본인의 지난 경기와 질문 흐름을 다시 확인할 수 있어야 한다.

## 3. 대상 사용자

- 포켓몬 전국도감 이름을 알고 지인과 가볍게 퀴즈를 즐기려는 사용자
- 모바일 또는 데스크톱 브라우저에서 1:1 실시간 게임을 하려는 사용자
- 지난 경기의 질문·답변·추측 기록을 다시 보고 싶은 사용자

## 4. 핵심 용어

- 방장: 방을 만든 회원
- 참가자: 방 코드로 입장한 두 번째 회원
- 출제자: 해당 경기의 정답 포켓몬을 고르고 질문에 답하는 회원
- 질문자: 질문하거나 정답 포켓몬을 추측하는 회원
- 행동: 질문 또는 포켓몬 추측 한 번
- 경기: 정답 포켓몬 선택부터 승패 확정까지의 한 판
- 재대결: 같은 방에서 역할을 바꿔 시작하는 다음 경기

## 5. 확정 게임 규칙

1. 로그인한 회원만 방을 만들거나 입장할 수 있다.
2. 한 방에는 정확히 두 명만 참여한다.
3. 첫 경기에서 방장이 출제자, 입장자가 질문자다.
4. 출제자는 전국도감 기본 종 가운데 한 마리를 고른다.
5. 질문자는 자유 텍스트 질문 또는 포켓몬 추측 중 하나를 실행한다.
6. 출제자는 질문에 `예`, `아니요`, `모르겠어요` 중 하나로 답한다.
7. 질문과 추측은 합쳐 최대 20회다.
8. 잘못된 포켓몬 추측도 1회를 사용한다.
9. 정답 추측은 20번째 행동에서도 즉시 질문자 승리로 끝난다.
10. 20번째 질문은 출제자가 답한 뒤 질문자 패배로 끝난다.
11. 연결이 예기치 않게 끊기면 경기를 일시정지하고 60초 동안 재접속을 기다린다.
12. 60초 안에 같은 회원이 돌아오지 않으면 이탈한 회원이 패배한다.
13. 사용자가 `게임 나가기`를 명시적으로 선택하면 유예 없이 기권 패배한다.
14. 두 참가자가 모두 재대결에 동의하면 역할을 바꿔 다음 경기를 시작한다.
15. 재대결 동의 전에는 다음 정답을 고를 수 없다.

## 6. 포켓몬 범위

- 전국도감 1~1,025번의 기본 포켓몬 종
- 2026-07-24 PokéAPI snapshot 기준 9개 세대
- 한국어 공식 이름
- PokéAPI sprites 저장소의 기본 `official-artwork`
- 제외:
  - 리전폼
  - 메가진화
  - 거다이맥스
  - 성별·자세 차이
  - shiny
  - fan-made sprite

catalog에 한국어 이름이나 기본 공식 일러스트가 빠진 종이 있으면 조용히 영어 이름으로 대체하지 않는다. snapshot 생성 검증을 실패시키고 누락을 먼저 보고한다.

## 7. 기능 요구사항

### 7.1 회원과 인증

- `FR-AUTH-01`: 로그인 ID, 비밀번호, 닉네임으로 가입한다.
- `FR-AUTH-02`: 로그인 ID와 닉네임은 대소문자·공백 정규화 뒤 각각 중복을 허용하지 않는다.
- `FR-AUTH-03`: 비밀번호 원문은 저장·로그 출력·응답 반환을 금지한다.
- `FR-AUTH-04`: 로그인 성공 뒤 서버 측 session을 발급한다.
- `FR-AUTH-05`: 비회원은 랜딩, 회원가입, 로그인만 접근한다.
- `FR-AUTH-06`: 로그아웃하면 session을 폐기한다.
- `FR-AUTH-07`: 한 회원은 동시에 하나의 활성 방에만 참여한다.
- `FR-AUTH-08`: 사용자 UUID를 게임 기록의 참조 기준으로 삼는다.
- `FR-AUTH-09`: 추후 이메일 인증을 추가해도 기존 사용자 UUID와 게임 기록은 유지한다.
- `FR-AUTH-10`: 로그인 session은 마지막 접근 뒤 30분 동안 활동이 없으면 만료한다.
- `FR-AUTH-11`: 단일 API instance에서 아래 인증 요청 제한을 적용한다.
  - login ID별 비밀번호 실패 5회/10분
  - client IP별 전체 login 시도 30회/10분
  - client IP별 전체 signup 시도 5회/10분

### 7.2 로비와 방

- `FR-ROOM-01`: 로그인한 사용자는 새 방을 만들 수 있다.
- `FR-ROOM-02`: 서버는 혼동 문자를 뺀 6자리 대문자·숫자 방 코드를 생성한다.
- `FR-ROOM-03`: 다른 사용자는 방 코드로 대기방에 들어간다.
- `FR-ROOM-04`: 존재하지 않음, 만료, 정원 초과, 자기 자신 중복 입장을 구분해 안내한다.
- `FR-ROOM-05`: 두 참가자는 상대 닉네임과 연결 상태를 본다.
- `FR-ROOM-06`: 대기 중인 빈 방은 생성 후 30분이 지나면 만료한다.
- `FR-ROOM-07`: 진행 중 뒤로가기·로그아웃·명시적 나가기는 기권 경고를 먼저 보여준다.

### 7.3 포켓몬 선택

- `FR-DEX-01`: 한국어 이름과 전국도감 번호로 검색한다.
- `FR-DEX-02`: 세대 필터와 페이지 탐색을 제공한다.
- `FR-DEX-03`: 목록에 도감 번호, 한국어 이름, 공식 일러스트를 표시한다.
- `FR-DEX-04`: 출제자만 정답 선택 화면에 접근한다.
- `FR-DEX-05`: 질문자에게 보내는 REST·STOMP payload, HTML, log에 정답을 포함하지 않는다.
- `FR-DEX-06`: 이미지가 불러와지지 않으면 정답을 추론할 수 없는 공통 placeholder를 표시한다.

### 7.4 실시간 경기

- `FR-GAME-01`: 질문자는 답변 대기 중 새 행동을 보낼 수 없다.
- `FR-GAME-02`: 질문은 1~200자로 제한하고 공백만 있는 질문은 거절한다.
- `FR-GAME-03`: 출제자는 pending 질문 하나에 한 번만 답한다.
- `FR-GAME-04`: 서버가 역할, 순서, 횟수, 상태 전이를 검증한다.
- `FR-GAME-05`: 클라이언트 재전송으로 같은 command가 두 번 적용되지 않게 한다.
- `FR-GAME-06`: 서버가 현재 사용 횟수와 남은 횟수를 계산한다.
- `FR-GAME-07`: 모든 참가자 화면에 질문, 답변, 공개된 오답 추측을 같은 순서로 표시한다.
- `FR-GAME-08`: 경기가 끝나기 전에는 정답 포켓몬을 질문자에게 공개하지 않는다.
- `FR-GAME-09`: 경기가 끝나면 정답, 승패, 종료 사유를 두 참가자에게 공개한다.

### 7.5 재접속과 이탈

- `FR-CONN-01`: WebSocket heartbeat 또는 disconnect event로 연결 종료를 감지한다.
- `FR-CONN-02`: 예상하지 못한 종료 시 상대에게 60초 재접속 대기 상태와 마감 시각을 표시한다.
- `FR-CONN-03`: 동일한 인증 session의 사용자가 같은 방 route로 돌아오면 역할별 최신 snapshot을 받는다.
- `FR-CONN-04`: 재접속 성공 시 기존 질문·답변·횟수·정답 선택을 유지한다.
- `FR-CONN-05`: 60초가 지나면 연결이 끊긴 사용자의 패배로 확정한다.
- `FR-CONN-06`: 두 사용자가 모두 끊긴 채 먼저 도래한 마감 시각까지 돌아오지 않으면 `BOTH_DISCONNECTED`로 중단하고 승패 통계에는 포함하지 않는다.
- `FR-CONN-07`: 서버 재시작으로 복구할 수 없는 경기는 `SERVER_RESTART`로 중단한다.

### 7.6 경기 기록

- `FR-HISTORY-01`: 아래 항목을 저장한다.
  - 경기 시작·종료 시각
  - 참가자와 역할
  - 정답 포켓몬
  - 승자·패자
  - 종료 사유
  - 순서가 있는 질문과 답변
  - 추측한 포켓몬과 정답 여부
  - 사용한 행동 수
- `FR-HISTORY-02`: 목록은 최신 경기부터 페이지 단위로 제공한다.
- `FR-HISTORY-03`: 상세 기록은 해당 경기 참가자만 조회한다.
- `FR-HISTORY-04`: 기록 화면에서 당시 역할과 결과를 현재 사용자 기준으로 표시한다.
- `FR-HISTORY-05`: DB에는 UTC로 저장하고 브라우저의 현지 시간대로 표시한다.

## 8. 화면과 route

| Route | 접근 | 책임 |
|---|---|---|
| `/` | 모두 | 서비스 소개, 로그인·회원가입 진입 |
| `/signup` | 비회원 | 회원가입 |
| `/login` | 비회원 | 로그인 |
| `/lobby` | 회원 | 방 생성, 방 코드 입장 |
| `/rooms/:roomCode` | 방 참가자 | 대기, 선택, 경기, 결과, 재대결 |
| `/history` | 회원 | 내 경기 기록 목록 |
| `/history/:gameId` | 경기 참가자 | 질문·답변·추측 상세 |
| `*` | 모두 | 404와 안전한 복귀 경로 |

브라우저 뒤로가기와 직접 URL 접근을 지원한다. 활성 경기에서 route를 벗어날 때 React Router navigation blocker로 경고한다. 탭 닫기나 브라우저 강제 종료는 완전히 막을 수 없으므로 disconnect·60초 규칙으로 처리한다.

## 9. 비기능 요구사항

### 보안

- 같은 출처 cookie session을 사용한다.
- 운영 cookie에 `HttpOnly`, `Secure`, `SameSite=Lax`를 적용한다.
- REST state change와 STOMP `CONNECT`에 CSRF 검증을 적용한다.
- 비밀번호는 Spring Security `DelegatingPasswordEncoder`로 해시한다.
- 인증 요청 제한 상태는 최대 크기와 10분 만료를 둔 Caffeine memory cache에 저장한다.
- login ID 제한에 도달하기 전 로그인에 성공하면 해당 ID의 실패 횟수를 초기화한다.
- client IP는 신뢰한 reverse proxy가 정규화한 servlet remote address만 사용한다.
- 정답 포켓몬은 역할별 DTO와 사용자별 STOMP queue로 분리한다.
- 질문·닉네임은 React text node로 렌더링하고 HTML 주입을 허용하지 않는다.
- DB, actuator 상세 정보, stack trace, 환경변수, session ID를 외부 응답과 log에 노출하지 않는다.

### 신뢰성

- 게임 command는 server-authoritative state machine에서 직렬 처리한다.
- command ID와 game action unique constraint로 중복 적용을 막는다.
- DB migration은 Flyway로만 적용한다.
- PostgreSQL healthcheck가 통과한 뒤 API를 시작한다.
- 활성 방은 단일 API instance 메모리에 둔다.

### 성능

- 첫 운영 목표는 단일 Mac mini와 소수 동시 방이다.
- catalog 1,025건은 PostgreSQL에서 검색하고 page size 상한을 둔다.
- 큰 이미지 파일을 서비스 이미지에 포함하지 않는다.
- 무근거 Redis, 외부 STOMP broker, Kubernetes, microservice 분리는 도입하지 않는다.

### 접근성과 반응형

- 모바일과 데스크톱에서 핵심 게임 흐름을 사용할 수 있어야 한다.
- keyboard focus, form label, live status 안내, 충분한 색상 대비를 제공한다.
- 연결 상태와 남은 횟수를 색상만으로 구분하지 않는다.

## 11. 완료 기준

- Docker만 설치된 Apple Silicon Mac에서 전체 서비스를 빌드·실행할 수 있다.
- 두 개의 독립 브라우저 session으로 회원가입부터 한 경기 종료·재대결까지 완료한다.
- 정상, validation, 인증, 인가, 중복 command, 20회 제한, 정답, 이탈, 재접속 실패를 자동 테스트한다.
- 질문자에게 전달되는 모든 경기 payload에 종료 전 정답이 없음을 자동 테스트한다.
- 본인이 참여하지 않은 경기 기록 상세 조회가 resource 존재를 숨기는 404를 반환한다.
- Docker를 재시작해도 회원과 완료된 경기 기록이 PostgreSQL volume에 남는다.
- `trycloudflare.com` 주소에서 SPA route, REST, cookie session, WebSocket을 통합 검증한다.
- 구현 결과와 미검증 항목을 작업 리뷰 문서에 기록한다.

## 12. 공개 운영 경계

- 서비스 footer에 비공식 비상업 팬 프로젝트임을 표시한다.
- 포켓몬 공식 서비스와 제휴·후원 관계를 암시하지 않는다.
- `POKEMON_ARTWORK_ENABLED`를 통해 공식 일러스트를 즉시 공통 placeholder로 전환할 수 있게 한다.
- 위 조치는 사용 권한을 보장하지 않는다. 실제 공개 배포 전 별도 권리 검토가 필요하다.
